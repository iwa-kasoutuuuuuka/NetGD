# MCU と FPGA のコマンド受け渡し（番号つき ack、番号つき Status、スロット 19 のマスク、スロット 5）

対象：`fpga/amaranth/hw/ide_device.py`（スロット 0・1・5・19）、`mcu/netgd/src/ide.rs`（`take_command`・`ack_command`・`post_status`・`clear_reset_seen`・`disarm`・`set_dma_mode`・`set_pio_flow_control`）。
レジスタの細部は `docs/AddressMapMCU.md`。きっかけは R89 の A-c と `docs/PLAN.md` の「将来の地雷メモ」。

**確認の範囲：FPGA のシミュレーションとファームのビルドだけ。実機では確かめていない。**
同梱のビットストリーム（`fpga/Quartus/output_files/OpenGDEMU.rbf`）は作り直していないので、Quartus で `out/OpenGDEMUCore.v` から作り直すまで、実機の動作は従来のまま。

## 1. 何が起きていたか（A-c）

ホストが Command レジスタに書くと、FPGA は `command_pend` を立て、MCU_IRQn を下げる。
ファームは `sweep` でレジスタを読み、処理し、スロット 0 に 0 を書いて `command_pend` を消していた（`ack_command`）。

この「0 を書く」は、どのコマンドの分かを問わずに消す。取りこぼす窓は2つあった。

1. **ソフトの窓**：ファームがレジスタを読んでから ack を書くまで。
   単純なハンドラ（NOP、SET FEATURES、IDENTIFY など）は「Status を書く → ack」の順なので、ホストが BSY=0 を見て次のコマンドを書くと、その直後の ack が次のコマンドの `command_pend` を消す。
2. **ハードの窓**：ack の書き込みストローブは FPGA の数クロック分の幅がある。`ide_device.py` では MCU 側の代入が後ろにあり、同じクロックでは MCU 側が勝つので、ストローブの最中に来た Command 書き込みの `command_pend.eq(1)` が負ける。

どちらも結果は同じ：次のコマンドは BSY=1 のまま、`command_pend` は 0、MCU_IRQn にエッジは出ない。ホストがタイムアウトするまで止まる。

## 2. 新しい取り決め

FPGA にコマンドの番号 `cmd_seq`（7 ビット、Command 書き込みごとに +1、リセットでは消さない）を足し、スロット 0 の読み出しに載せた。

| ビット | 読み | 書き |
|---|---|---|
| 1 | COMMAND_PEND | 下の表 |
| 2 | RESET_SEEN | 1 で消す（従来どおり） |
| 14:8 | `cmd_seq` | ack する番号 |
| 15 | 1（番号つき ack に対応） | 書き込みの形式 |

| 書き込み | 動作 |
|---|---|
| bit15=0（従来の形式） | COMMAND_PEND ← bit1。0 なら無条件に消える |
| bit15=1、bit1=0 | bit 14:8 が現在の `cmd_seq` と同じで、かつそのクロックに Command 書き込みが無いときだけ消す |
| bit15=1、bit1=1 | COMMAND_PEND は変えない（RESET_SEEN だけ消すとき用） |

ファームの手順：

1. `take_command`：スロット 0 を読む → レジスタを取り込む → スロット 0 をもう一度読む。上位バイトが同じになるまで取り込み直す。その上位バイトを `ACK_TOKEN` に置く。
2. `ack_command`：`ACK_TOKEN` をそのままスロット 0 に書く（bit1=0）。
3. 取り込みより後に来たコマンドは番号が違うので `command_pend` が残る。`sweep` の `while dev.command_pending()` と `ide_task` の内側のループ（どちらもレベルで見る）が次の周で拾う。MCU_IRQn は上がらないのでエッジは出ないが、レベルで見ているので要らない。

2回読む理由は2つ。取り込んだレジスタと番号を同じコマンドのものにそろえる。また `cmd_seq` は FPGA のクロックで変わるので、MCU の1回の読みが変わり目にかかると新旧のビットが混ざりうるが、2回続けて同じ間違った値にはならない。

### 新旧の組み合わせ

| ファーム | ビットストリーム | 動作 |
|---|---|---|
| 新 | 新 | 番号つき ack |
| 新 | 旧 | 上位バイトは 0 と読める → 0 を書く → 従来の無条件 ack |
| 旧 | 新 | 0 を書く → 従来の形式 |

どちらの側も相手の版を調べない。

### 直していないこと

- ~~単純なハンドラは `complete()` を通さずに Status を書く。古いコマンドの Status が新しいコマンドの BSY を消す。~~ → 2.1 で対処した。
- Error（スロット 3）、割り込み理由（スロット 5）、バイト数など、Status より前に書くレジスタには番号を付けていない。古いコマンドの値が新しいコマンドのレジスタに乗りうる。Status が落とされるのでホストはまだ BSY=1（PACKET なら CDB フェーズ）を見ており、新しいコマンドのハンドラが完了の前にこれらを書き直す。
- `handle_packet` は最初にレジスタをもう一度読む。`take_command` のあとにホストがレジスタを書き換えていれば、そちらを見る。
- ホストが処理中にタスクファイル（LBA など）だけを書き換えた場合は検出しない。番号は Command 書き込みしか数えない。

## 2.1 Status の書き込みにも番号を付ける

### 残っていた競合

ファームがコマンド A の Status を決めてからスロット 1 に書くまでの間に、ホストがコマンド B を書く場合。

1. ホストが B を Command に書く。FPGA は BSY=1・DRQ=0・`command_pend`=1・`cmd_seq`+1 にする（PACKET なら BSY=0・DRQ=1 で CDB フェーズを開く）。
2. A の Status（たとえば 0x50 と INTRQ）がスロット 1 に届く。従来の書き込みは無条件なので、B の BSY が落ち、INTRQ が立つ。
3. ホストは B の結果として A の Status を読む。PACKET では DRQ が消えるので CDB を送れない。B の `command_pend` は残っているので、ファームはそのあと B を処理するが、ホストはもう先へ進んでいる。

窓は ack と同じく2つある。

- **ソフトの窓**：ファームが Status を決めてから書くまで。`complete()` は書く直前に COMMAND_PEND を見るが、見てから書くまでの間は残る。単純なハンドラは見ずに書く。
- **ハードの窓**：Status の書き込みストローブは FPGA の数クロック分あり、`ide_device.py` では MCU 側の代入が後ろにある。ストローブの最中に来た Command 書き込みの `bsy.eq(1)` と `intrq_pending.eq(0)` が負ける。

ハードの窓はファームからは閉じられない。ファームがどれだけ直前に確かめても、確かめた読みと書き込みは別のバスアクセスで、その間とストローブの最中に FPGA のクロックは進む。比較と書き込みを同じクロックで行えるのは FPGA だけなので、FPGA 側で直した。

### 取り決め

スロット 1 の書き込みの bit 15:9 を使う（bit 7:0 が Status、bit 8 が INTRQ なのは従来どおり）。

| 書き込み | 動作 |
|---|---|
| bit15=0（従来の形式） | 無条件に書く |
| bit15=1 | bit 14:9 が現在の `cmd_seq` の下位 6 ビットと同じで、かつそのクロックに Command 書き込みが無いときだけ書く。違えば Status も INTRQ も変えない |

- ファームは `post_status` 1か所で `ACK_TOKEN`（`take_command` が取った上位バイト）から bit 15:9 を作る：`(t & 0x8000) | ((t << 1) & 0x7E00)`。`set_status`・`set_status_intrq` はどちらもここを通るので、ハンドラの呼び出し側は変えていない。
- 落とされた書き込みの後始末は要らない。B は latch されたままで、`sweep` が次に取り、B の番号で Status を書く。
- 6 ビットなのは bit 8 が INTRQ で埋まっているため。古い Status が通るのは、取り込みから書き込みまでの間に Command 書き込みがちょうど 64 回（または 128 回）あったときだけ。
- `complete()` の「COMMAND_PEND が立っているのに Command レジスタが 0x00」の経路だけは従来の形式で書く。この latch が Command 書き込みを伴っていた場合、番号が進んでいて番号つきの書き込みは落とされるため。この経路の動作は変えていない。
- `complete()` の COMMAND_PEND の確認は残した。古いビットストリームではこれだけが頼りで、新しいビットストリームでもログが出る。

### 新旧の組み合わせ

| ファーム | ビットストリーム | 動作 |
|---|---|---|
| 新 | 新 | 番号つき Status |
| 新 | R100（番号つき ack だけ） | bit 15:9 は無視される → 従来の無条件の書き込み |
| 新 | R100 より前 | スロット 0 の上位バイトが 0 → bit 15:9 も 0 → 従来の形式 |
| 旧 | 新 | bit 15=0 → 従来の形式 |

### 確認

`fpga/amaranth/test.py` に 3 件追加。変更前の `ide_device.py` では 3 件とも失敗し、変更後は通る。

- `stale_status_keeps_bsy_of_next_command`：ソフトの窓。B の BSY と、PACKET の CDB フェーズの DRQ が残ること、INTRQ が立たないこと、B の番号で書けば届くこと。
- `status_strobe_does_not_clear_bsy_of_command_write`：ハードの窓。ストローブと Command 書き込みの位置関係を 12 通り。`& ~cmd_wr` を外すと失敗することも確かめた。
- `status_write_forms`：従来の形式が無条件のままであること、ずれた番号 63 通りがすべて落とされること、番号が 6 ビットを一周しても現在の番号は通ること。

実機では確かめていない。同梱の `.rbf` は作り直していない。

## 3. スロット 19（DMA モード、PIO フロー制御、PKT_PHASE）

1語に持ち主の違うビットが入っている。DMA モード（bit 1:0）と PIO フロー制御（bit 2・3）はファームのもの、PKT_PHASE（bit 4）は FPGA が PACKET の Command 書き込みで立てるもの。従来はどの書き込みも5ビット全部を書いた。

実害のある組み合わせが1つあった：ホストが転送を捨てて新しい PACKET を書く → FPGA が PKT_PHASE を立てる → ファームが中断に気づいて `disarm()`（0 を書く）→ PKT_PHASE が消える → CDB の 6 語目で BSY が上がらず DRQ が残る。

対処：bit 12:8 を書き込みマスクにした（bit 8+n が 1 のとき bit n を書く。マスクが 0 なら従来どおり5ビット全部）。ファームはマスク `0x0F` で書く。

- **DMA モードとフロー制御は、わざとまとめて書く。** 転送は DMA か PIO のどちらかなので、この3つは1つの「転送モード」。まとめて書けば、後始末なしで終わった転送の残りも次の設定で消える（従来と同じ自己回復）。「片方を書くともう片方が消える」は地雷ではなく取り決めとして `ide.rs` と `AddressMapMCU.md` に書いた。別々に変えたい呼び出しが出てきたら、狭いマスクで書ける。
- **PKT_PHASE はファームから書かない。**

別々のマスク（`set_dma_mode` は `0x03`、`set_pio_flow_control` は `0x0C`）にしなかった理由：実機で確かめた経路は「書けば全部決まる」動作に乗っている。別々にすると、後始末を忘れた経路で古いフロー制御が残り、`bsy_out`・`drq_out` に効く。実機で試せない今は、動作を変えるのは PKT_PHASE の保護だけにした。

## 4. スロット 5（セクタカウント／ATAPI の割り込み理由）

MCU からの書き込みは下位バイトだけに届くようにした。上位バイト（ホストが前回書いた値、LBA48 で HOB=1 のとき読む）は MCU からは書けない。`set_irr` はファーム側の変更なしで上位バイトを消さなくなる。

- スロット 5 には空きビットが無いのでマスクは付けられない。ファームで読んでから書く方法は、原子的でないうえ、`set_irr` は 30 か所ほどから呼ばれ、2E の `resident,sd-fast` に余裕が無い。
- 失うもの：MCU が上位バイトを書く手段。今のファームは 0 以外を書いたことがなく、READ/WRITE (DMA) EXT の結果としてセクタカウントを返す必要もない。要るようになったら別スロットを足す。
- 旧ビットストリームでは従来どおり上位バイトが 0 になる（パケットデバイスではホストが読み返さない値）。

## 5. 確認

- `fpga/amaranth/test.py` に 6 件追加。変更前の `ide_device.py` ではすべて失敗し、変更後は通る。
  - `ack_keeps_command_written_after_snapshot`：ソフトの窓。
  - `ack_strobe_does_not_swallow_command_write`：ハードの窓。ack のストローブと Command 書き込みの位置関係を 12 通り。`& ~cmd_wr` を外すと失敗することも確かめた。
  - `hw_info_numbered_write_forms`：書き込みの形式、従来の形式の互換、番号の進み方。
  - `slot19_masked_write`・`disarm_keeps_packet_phase`・`irr_write_keeps_sector_count_prev`。
- 既存のシミュレーション（`test.py`・`test_cdda.py`・`test_timing.py`・`test_top.py`・`test_fifo.py`）は変更なしで通る。これらは従来の形式（スロット 0 に 0、スロット 19 にマスクなし）で書いているので、互換の確認にもなっている。
- 実機で見たいこと：BIOS の起動、DMA の CD_READ、WinCE のタイトル（割り込みの出方に厳しい）、DreamShell のディスク読み書き。新しいビットストリームと古いビットストリームの両方で。
