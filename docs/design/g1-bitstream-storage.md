## 0. 要約

1. **6.0 では SD の `NETGD.BIT` を正とする設計を今から作る（案 b）。埋め込み（案 a）は「入ると分かったら使う」ビルド時の選択肢として残す。**
   理由は数字：ローダー込みのアプリのコードは **69.1 KB** [測定]。埋め込める上限は常駐部なしで **62.0 KB**、常駐部ありで **53.5 KB**、
   コードの伸びしろ 8 KB を残すなら **53.8 KB / 45.3 KB**。見積もりは 55〜75 KB（今回の模擬では 61〜84 KB）で、**常駐部ありではほぼ入らない**。
2. **PLAN などにある「v60 のイメージは 65,536 B」は、ローダーと LZMA が消えた値である。** ビットストリームが無いビルドでは
   `BITSTREAM_PRESENT == false` のため、ローダー一式（3,934 B）がリンク時に落ちている [測定、§1-1]。予算の計算には 69.1 KB を使うこと。
3. **圧縮の工夫（案 d）では足りない。** LZMA の辞書・lc/lp/pb を変えても 2 % 前後 [測定・模擬]。0 の連長圧縮は AG16K には効かない
   （空の設計でも非 0 のバイトが 45 % ある [測定]）。効く可能性があるのは AGM 自身の圧縮（LZW、FPGA が展開する）だけで、大きさは [不明]。
4. **SD のファイルは「生の PS ストリーム（`.rbf` そのまま）＋ 512 B のヘッダ」にする。LZMA はかけない。** 552 KB の読み出しは 0.1〜0.3 秒 [推測] で、
   LZMA の展開（0.1〜0.5 秒 [推測]）と同程度。デコーダが要らなくなり、AGM 圧縮の `.rbf` に替えるのもファイルの差し替えだけで済む。
5. **起動時間への影響は小さい。** いまも「FPGA → SD 初期化 → マウント → IDE タスク」の順で全部終わるまで IDE は応答しない（`main.rs:153-204`）。
   SD 初期化を FPGA の前に移すだけなので、**IDE が応答し始める時刻はほぼ同じ**（±0.3 秒 [推測]）。延びるのは「バスが無応答の時間」で、SD 初期化のぶん +0.1〜0.6 秒 [推測]。
6. **文鎮にはならない。** `NETGD.BIT` が無い・壊れている場合、MCU のファームは無傷で、LED で理由を示して待つ。直し方は「PC でカードにファイルを置く」。
   ただしその状態では FPGA が無いので **BBA 経由では直せない**（`0xF9` も SD 書き込みも FPGA が要る）。だから BBA での更新は旧ファイルを残す 2 世代方式にする（§5）。
7. 代償：**カードごとに `NETGD.BIT` が要る**（純正 GDEMU 用に作ったカードはそのままでは動かない）、カードなしでは Dreamcast から見てドライブが無い。

### 1-4 圧縮を変える実験（案 d）[測定・模擬]

`xz --format=raw --lzma1=preset=9e,...` で、パラメータだけを変えた。

| 入力 | 4 KiB・lc0 lp0 pb0（今） | 8 KiB | 4 KiB・pb2 | 4 KiB・lp2 pb2 | 64 KiB | 1 MiB・lc3 pb2 | gzip -9 |
|------|------:|------:|------:|------:|------:|------:|------:|
| `blinky16k.bin`（552,366） | 10,403 | 9,219 | 10,456 | 10,465 | 3,801 | 3,661 | 9,936 |
| Cyclone II `.rbf`（73,821、Quartus 圧縮済み） | 49,629 | 49,532 | 49,711 | 50,579 | 49,080 | 49,458 | 51,343 |

模擬：Cyclone II 大の 0 のバッファ（158,224 B）に乱数でビットを立て、LZMA が 44.6 KB（実物の非圧縮→LZMA の値、`build.rs` の注釈）になる本数 N を求め、
同じ N を `blinky16k.bin` の一部（デバイスの 17〜23 %。資源の使用率 R39）に立てて圧縮した。

| 模擬の条件 | 4 KiB | 8 KiB | 0 連長のみ | 0 連長 → LZMA |
|-----------|------:|------:|-----------:|--------------:|
| N = 58,319 本を 17 % の範囲に | 61,205 | 59,982 | 508,785 | 66,717 |
| 同、23 % の範囲に | 69,223 | 67,788 | 511,890 | 75,186 |
| N = 91,454 本（別の較正）を 17 % に | 72,591 | 71,302 | 510,684 | 78,857 |
| 同、23 % に | 84,165 | 82,823 | 515,914 | 90,888 |

読み取れること：

- **辞書を 8 KiB にしても 約 2 %（1.2〜1.4 KB）。** RAM は足りる（スクラッチ 7,646 → 11,742 B、`CD_READ_BUF` は 14,336 B）が、境目を動かすほどではない。
  64 KiB 以上は 2E の RAM（合計 36 KB）に入らない。lc を上げると確率表が `0x300 << lc` に増える（`common/lzma/src/lib.rs:6-8`）。lp・pb は効かないか悪化。
- **0 の連長圧縮は AG16K には使えない。** `blinky16k.bin` は 552,366 B のうち非 0 が 246,870 B（45 %）で、連長だけでは 488 KB にしかならない。
  空の設計にも周期的な既定値が並んでいるためで、縮めるには周期の一致を拾う LZ 系が要る。LZMA の前段に置くと逆に悪くなる（上の表）。
- 模擬は「設定ビットが乱数」という最悪寄りの仮定で、数字そのものは当てにしない。ただ **55〜75 KB の下側に入る根拠は出てこなかった**。
- **圧縮で境目をまたげる可能性があるのは AGM の LZW だけ。** AG16K は PS でも圧縮ストリームを受ける [一次、`ag16k-config.md` §2-4]。
  純正 6.0 はカードに専用ファイルを要求しないので、純正のビットストリームは 128 KB のフラッシュにコードと一緒に入っているはず [推測]。
  `fwbackup dump` が取れれば、純正がどの形で何 KB 使っているかが分かる（§8 H8）。

## 3. 案 b の設計

### 3-1 SD は FPGA なしで読めるか

読める。SD は MCU の HSMCI 直結で、初期化（`sdcard.rs:74-185`）も読み出し（`hsmci.rs:891` `read_blocks_dma`、MCU の DMAC）も FPGA のレジスタに触れない。
`hsmci::init` は HAL の初期化で済んでいる（`embassy-atsam3/src/lib.rs:150`）。常駐部の SD 復旧が FPGA なしで成り立つのと同じ理由（`fw-bootloader.md` §2-1）。

### 3-2 ファイル

- 場所と名前：カードのルートの `NETGD.BIT`（現行）、`NETGD.BAK`（1 つ前）、`NETGD.NEW`（書き込み途中）。8.3 名。
- 中身：**512 B のヘッダ ＋ PS に流すバイト列そのまま（`.rbf`）＋ 512 の倍数までの詰め物**。LZMA はかけない。
  - LZMA にしない理由：(1) 今の `lzma::Decoder` は入力をスライスで受ける（`common/lzma/src/lib.rs:111,133`）ので、55 KB 超の入力を RAM に置けない 2E では
    デコーダの入力側を作り直す必要がある、(2) 読み出し 552 KB は 2〜5 MB/s で 0.1〜0.3 秒 [推測]、展開は 0.1〜0.5 秒 [推測] で得にならない、
    (3) デコーダ（約 1 KB）とスクラッチ 7.6 KB が要らなくなる、(4) AGM 圧縮の `.rbf` に替えるとき、ファームを変えずに済む。
- ヘッダ：OGFW 形式 3 のヘッダ（`FORMAT.md:24-36`）に **`kind = 2`（SD のビットストリーム、フラッシュには書かない）** を足す案。

  | 語 | 内容 |
  |----|------|
  | w0〜w1 | `"OGFW"`、`format = 3` |
  | w2 | `kind = 2` |
  | w3 | `target_cidr`（2E `0x281A0761`。基板の系統の取り違え防止） |
  | w4 | `dest = 0` |
  | w5 | `len`：詰め物込みのペイロード長（512 の倍数、上限 `0x100000`） |
  | w6 | `payload_crc`：ペイロード全体の CRC-32 |
  | w7 | `image_version`：ビットストリームのビルド番号（表示用） |
  | w8 | `header_crc`：バイト 0..31 と 36..63 の CRC-32（kind 2 だけ範囲が広い） |
  | w9 | 0 |
  | w10 | `raw_len`：流すバイト数（552,366 など） |
  | w11 | `encoding`：bit0 = ビット順（0 = LSB 先頭 `.rbf`、1 = MSB 先頭 `.bin`）。ほかは 0 |
  | w12 | `iface`：FPGA とファームの取り決めの版（上位 16 = 互換の世代、下位 16 = 追加） |
  | w13 | FPGA のデバイス ID（AG16K の `.bin` 内の `0x01500010`、`ag16k-config.md` §2-2） |

  - **既存の受け手は kind 2 を必ず拒否する**：`mcu/bootcore/src/ogfw.rs:71` と `mcu/fwupdater/src/logic.rs` の kind の検査は 0 と 1 以外を `BadHeader` にする。
    つまり `NETGD.BIT` を `0xF9` に流しても、`NETGD.OGF` という名前で置いても、フラッシュには 1 バイトも書かれない。
  - ビット順をファイルに持たせるので、`ps-msb-first`（`Cargo.toml` の feature、`cyclone.rs:31-34`）はビルドし直さずに試せるようになる。
- 作るのは `fwimage.py`（新しいサブコマンド `bitfile --rbf … --iface N -o NETGD.BIT`、`inspect` に kind 2）。`tools/mksdcard` はカードを作るときに置く。

### 3-3 起動の流れ（アプリ。常駐部は関与しない）

```
main_task（feature bitstream-sd）
 1. ローダーのピンを Low に（今と同じ。main.rs:76-82）
 2. sdcard::init()                    … 失敗 → LED 5、1 秒おきにやり直す（後から挿しても進む）
 3. fat::probe() → ルートで候補を順に探す：NETGD.BIT → NETGD.BAK → NETGD.NEW
      候補ごとに先頭 1 ブロックを読み、ヘッダを検査（CRC、kind 2、CHIPID、デバイス ID、iface の世代がファームの期待と同じ）
      合わない候補は飛ばす。どれも無い → LED 6、合うものが無い → LED 7 / 8
 4. fat::map_extents() でファイルを連続ブロックの並びにする
 5. cyclone::load(&mut pins, || SdSource::new(extents, header))
      SdSource は 8 KB（16 ブロック）ずつ CMD18 で CD_READ_BUF に読み、1 バイトずつ渡す。CRC を計算しながら進む
      **最後の 8 KB は、ファイル全体の CRC が合ったことを確かめてから渡す**（§3-4）
      読み取りエラー・CRC 不一致 → failed() が真 → psload がやり直す（AG16K は再試行 3 回、psload/src/lib.rs:160）
      それでもだめなら次の候補へ
 6. 成功 → 10 ms 待つ → FPGA の版レジスタを読み、ヘッダの iface と照合 → 違えば nCONFIG を Low に戻して LED 8
 7. 以降は今と同じ（マウント → プリフェッチ → IDE タスク）。SD は 2 で初期化済みなので main.rs:156 の init は呼ばない
```

- 既存の部品で足りる：`fat::probe`（`fat.rs:94`）、`find_in_dir`（`fat.rs:185`）、`map_extents`（`fat.rs:219`）、`read_blocks_dma`（`hsmci.rs:891`、1 回 128 ブロックまで）、
  `ide::loader_scratch()`（`ide.rs` の `loader_scratch`。今も LZMA のスクラッチとして同じ場面で借りている、`main.rs:92-102`）。
- `psload` は変更不要。`PsSource`（`psload/src/lib.rs:46-55`）に「途中で壊れた」を伝える口が既にあり、`load_with_retries` は試行ごとにソースを作り直す。

### 3-4 完全性：壊れたファイルで FPGA を動かさない

- **ヘッダ**は流す前に検査する（1 ブロック）。違う基板用・違う世代・壊れたヘッダでは nCONFIG のパルスも出さない。
- **本体**は 1 回読みで流しながら CRC を計算し、**末尾のチャンクを流す前に CRC を確定させる**。FPGA は最後まで受け取るまで CONF_DONE を上げず、
  ユーザーモードに入らない（Cyclone と同じ作法という前提 [推測]）ので、CRC が合わないファイルでは設計が 1 度も動かない。合わなければ nCONFIG を Low に戻す。
  時間の追加は 0。末尾のチャンクは RAM（`CD_READ_BUF`）に持ったまま判定する。
- 前提が実機で崩れた場合（末尾を欠いても CONF_DONE が上がる、§8 H3）の代替：**2 回読み**（1 回目は CRC だけ、2 回目に流す）。+0.1〜0.3 秒 [推測]。
- FPGA 自身の CRC 検査（nSTATUS が落ちる）があるかは [不明]（`ag16k-config.md` §2-2）。あれば二重の守りになるが、当てにしない。
- 読み出しの間（8 KB で 2〜4 ms [推測]）は DCLK が止まる。PS は DCLK を止めてよい作法だが、AG16K での確認は要る（§8 H2）。

### 3-5 失敗時の表示と振る舞い（文鎮にしない）

`psload::PsError::code`（`psload/src/lib.rs:201-207`）は 1〜5 を使っている。5（`NoBitstream`）の意味を広げ、6 以降を足す。

| LED の回数 | 意味 | 自動のやり直し |
|-----------:|------|----------------|
| 1〜4 | 今のまま（nSTATUS が上がらない／途中で落ちた／CONF_DONE が来ない／データが壊れた） | 1〜3 は今のまま再試行 |
| 5 | カードが無い・初期化できない | 点滅のたびに SD を初期化し直す |
| 6 | カードは読めるが `NETGD.BIT`（と `.BAK`・`.NEW`）が無い、または FAT32 でない | 同上（差し替えを待つ） |
| 7 | ファイルはあるが受け付けない（ヘッダ・CRC・基板違い・大きさ） | しない |
| 8 | ファームと FPGA の版が合わない | しない |

- どの場合も MCU は動いたまま、SWD も常駐部の SD 復旧（`NETGD.OGF`）も使える。直し方は「PC でカードに `NETGD.BIT` を置いて電源を入れ直す」。
- 常駐部の点滅コード（`fw-bootloader.md` §2-3 の 2〜9）と回数が重なる。**点滅の速さか前置きの長い点灯で、常駐部とアプリを区別する**（D5）。
- 6.0 の LED のピンは未確認（v5.5 は PB18、`cyclone.rs:193`）。
- カードなしのとき、Dreamcast の BIOS が無応答のバスをどう扱うかは [不明]（`fw-bootloader.md` の H7 と同じ項目）。

### 3-6 RAM

| 用途 | 大きさ | 置き場所 |
|------|-------:|----------|
| 読み出しチャンク（16 ブロック） | 8,192 B | `CD_READ_BUF`（SRAM1、14,336 B。最初の CD_READ まで空いている） |

- 案 b では「マウントを FPGA より先に済ませる」こともできる（FPGA が動いた直後に IDE が応答する）。無応答の時間が延びるので既定にはしない。実測してから決める。

## 5. 更新の経路

### 5-1 PC で

カードを PC に挿して `NETGD.BIT` を上書きする。失敗しても PC でやり直せる。`mksdcard` と配布物に必ず入れる。

### 5-2 BBA 経由（Dreamcast 側のアプリが書く）

FAT を持っているのは Dreamcast 側（KOS + FatFs、`tools/netgd-recv`）。`netgd-fwupd` は `0xF9` だけで FAT を持たないので、**書くのは `netgd-recv` の新しい操作**にする。

```
sysput NETGD.BIT:
 1. NETGD.NEW を連続領域に確保して書く → 読み戻して照合（既存の FNV-1a の仕組み）
 2. NETGD.BAK があれば消す
 3. NETGD.BIT を NETGD.BAK に改名
 4. NETGD.NEW を NETGD.BIT に改名
```

- どの時点で電源が切れても、`BIT`・`BAK`・`NEW` のどれかに検査を通るファイルが残る。ファームは §3-3 の順で探すので次の起動で FPGA は起きる。
- PC 側（`netgd-send`）が送る前に `fwimage inspect` で kind 2 を検査する。Dreamcast 側は転送の照合だけでよい（C に検査を持たせるかは D6）。
- 反映は次の電源投入から（動作中に FPGA を作り直すと IDE が消えるので、その場では切り替えない）。
- 書き込みセッションの保護（F7 の MBR 保護）はルートのファイルを守らない。`netgd-recv` 側で名前を `NETGD.BIT` に限る。

### 5-3 ファームと FPGA を一緒に替える（取り決めの世代が変わるとき）

順序：**先にビットストリーム、次にファーム。**

1. 新しい `NETGD.BIT`（新世代）を §5-2 で置く。古い方は `NETGD.BAK` に残る。
2. この時点で電源を入れ直しても、古いファームは世代の違う `BIT` を飛ばして `BAK` で起きる。
3. `netgd-fwupd` でファームを更新（`0xF9`）。新しいファームは `BIT` で起きる。
4. ファームの更新が途中で切れた場合：常駐部があれば `NETGD.OGF` から復旧する。**カードの `NETGD.OGF` は `BIT` か `BAK` のどちらかと同じ世代にしておく**（手順書に書く）。

## 6. 常駐部（`bootcore`）との関係、常駐部なしの場合

- **常駐部は `NETGD.BIT` を読まない。** R56 の D2（I-B：常駐部は FPGA を起こさない）のまま。`mcu/bootcore/src/fat.rs:66` の `NAME_BITSTREAM` は定義だけで、どこからも使われていない [一次、grep]。
  つまり `NETGD.BIT` の名前も形式も常駐部には凍らない。**ロックする前にこの定数は消すか、「アプリが読む」と注釈を直す**（誤解のもと）。
- 常駐部の復旧（`NETGD.OGF` → アプリ領域）は、案 b ではイメージが 約 70 KB になり速くなる（EWP が 464 → 約 275 ページ）。
  復旧後のアプリは同じカードの `NETGD.BIT` で FPGA を起こす。**復旧用のカード 1 枚に `NETGD.OGF` と `NETGD.BIT` の両方を置く**のが配布の形。
- アプリの記述子（`resident.rs:37-41,65-88`、`FORMAT.md:90-101`）：ビットストリームの種別に **2 = SD（必須）** を足す。番地は 0、
  「圧縮後の長さ」の語に期待する `iface`、「展開後の長さ」の語は 0。`FORMAT.md:107` のとおり語 12〜27 は常駐部が検査しないので、常駐部は変更不要。
- 2E の 1 プレーンでは、埋め込みならビットストリームもイメージの CRC に入る（R60）。SD ではイメージの CRC の外になり、ファイル自身の CRC が守る。
- **常駐部なしの場合**：設計は同じ。違うのは境目だけ（§1-2：62.0 KB、伸びしろ込み 53.8 KB）。`NETGD.BIT` が無い場合の振る舞いも同じで、ファームの復旧手段が SWD だけになる点は今と変わらない。
- 埋め込みが成り立つ場合（X ≤ 45 KB）の併用の順序：**埋め込みを先に試し、失敗したとき（LED 1〜4 相当）か開発用 feature のときだけ SD を見る。**
  毎回 SD を先に見ると、埋め込みの利点（SD を待たない）が消える。
