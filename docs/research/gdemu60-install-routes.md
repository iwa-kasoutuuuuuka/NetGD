# GDEMU 6.0 への NetGD の導入経路（SWD が応答しない場合）

2026-11-22、Opus（調査と文書のみ。実機の操作・ダウンロードはしていない）。
前提：LOG R177（Pico + debugprobe 2.3.1 + probe-rs 0.32.0 で、6.0 の 7 ピンヘッダから DP がまったく応答しない）。
根拠の印：**[一次]** 公式ページ・データシート・本リポジトリのコード／**[二次]** フォーラム・記事・検索要約／**[推測]**／**[不明]**。

法的・倫理的な範囲：純正ファームとその更新ファイルは取得・複製・引用・再配布しない。署名・暗号の回避や、純正の保護を破る方法は扱わない。
公開されている手順と挙動を要約するだけにとどめる。

---

## 0. 要約

1. **純正の更新方法は公開されているが、ファイル形式は公開されていない。** 手順は「`GDEMU.FW` を SD のルートに置き、ライトプロテクトを LOCK にして電源を入れる」[一次]。
   署名・暗号化の有無、ブートローダーの検査内容、版の比較は公式に書かれていない [不明]。
2. **純正の更新経路で NetGD を入れるのは現実的ではない。** 純正ブートローダーが受け付ける形式が非公開で、
   第三者のイメージを通すには保護を調べて回避することになる。本書ではこの方向を扱わない（§2）。
3. **NetGD の設計は「最初の 1 回は SWD（必要なら ERASE の後）、以降は `0xF9` か SD の `NETGD.OGF`」が前提**（§3）。
   SWD が使えないと最初の 1 回が入らず、NetGD 側の工夫では埋まらない。
4. **R177 の症状は、セキュリティビットで説明できる可能性が R177 の見立てより高い。** 上流の作者は INSTALL.md §6 に
   「純正ファームはセキュリティビットを立てており、デバッグポートが完全に切れる」「配線ミスではない」と書いている（v5.x の純正基板の経験談）[二次]。
   データシートの文面だけでは「DP は ID を返す」と読めるが、実機の報告とは合わない。JTAGSEL・TST・Pico の故障は依然として否定できていない。
5. **次の一手（安価な順）**：Pico の自己テスト（別ターゲット）→ ヘッダ 6 番（NRST 推定）の確認と connect-under-reset の可否検討 → JTAGSEL・TST の無電源での抵抗測定 → JTAG での IDCODE。
   それでも DP が見えなければ、**残るのは ERASE（純正ファームの永久消去）だけ**で、これはユーザーの判断（§5）。

## 2. 純正ブートローダーが第三者のイメージを受け付けるか

- 公開されている事実だけでは、**受け付けるとも受け付けないとも言えない**。形式・検査・署名の有無がどれも非公開だからである。
- 受け付けさせるには、純正の更新ファイルかブートローダーを解析して形式と検査を突き止めることになる。
  前者は純正の更新ファイルの入手と解析、後者は保護されたフラッシュの読み出しが前提で、**どちらも本プロジェクトの方針（純正を複製・再配布しない、保護を破らない）の外**。
  本書では手順を検討しない。
- 仮に形式が分かっても、純正ブートローダーが残る限り NetGD の常駐部（`mcu/bootcore`）と配置が衝突する（NetGD はフラッシュ先頭 `0x80000` からの全域を前提にする。§3）。
  純正の更新経路は「NetGD を入れる道」にはならず、せいぜい「NetGD を入れるための小さな踏み台」になるだけで、それも上の理由で扱わない。
- **結論：この経路は不採用。** 将来、販売元や作者が形式と第三者イメージの扱いを公式に公開した場合にだけ見直す。

## 3. NetGD の設計が前提にしている導入経路

### 3-1 文書とコードの前提 [一次、本リポジトリ]

| 場所 | 前提 |
|------|------|
| `INSTALL.md` §2〜§7 | 最初の書き込みは **SWD**（Pico + debugprobe、probe-rs か OpenOCD）。純正の基板は §6 で **ERASE（フラッシュ全消去・セキュリティビット解除）してから** §7 で書く。NetGD はセキュリティビットを立てないので、以後は ERASE 不要 |
| `INSTALL.md` §6 の 6.0 の注記 | ERASE は純正ファームを永久に消す。純正を捨てると決めるまで触らない。`fwbackup` で読めるなら先にバックアップ |
| `tools/fwbackup/README_ja.md` | 読み取り専用（`list`・`info`・`read` だけ許可）。`--connect-under-reset`・`reset`・`erase` などは拒否。`NO_TARGET` は配線不良とロックを区別できない、と明記 |
| `mcu/fwupdater` | 2 回目以降の更新：IDE のベンダーコマンド `0xF9`（`netgd-fwupd` を dcload-ip から）。RAM（SRAM1）から EEFC を直接操作。**NetGD が既に動いていることが前提** |
| `tools/fwimage`（`FORMAT.md`） | OGFW 形式 2（常駐部なし）・形式 3（常駐部あり）。対象 CHIPID・宛先・CRC を検査。**署名は無い**（自前の基板の誤書き込み防止が目的） |
| `docs/design/fw-bootloader.md`（B-SD）・`mcu/bootcore` | 8 KB の常駐部をフラッシュ先頭に置いて自己ロック。アプリが無効・ボタン・アプリの要求のときに **SD の `NETGD.OGF`** から書き直す。**常駐部の導入そのものは SWD**（D3：当面は SWD、移行イメージは作らない）。常駐部の更新も SWD だけ |
| `docs/research/stock-gdemu-flow.md` | 一度 NetGD が入れば、`0xF9` で SWD なしに「書き換え → プローブ → 比較」を回せる |

### 3-2 想定している流れ

```
純正 6.0 ──(SWD で読めれば fwbackup でバックアップ)──┐
         ──(ロックなら ERASE：純正は消える)──────────┤
                                                    ▼
                      SWD で NetGD（+ 将来は常駐部）を書く（INSTALL §7）
                                                    ▼
               以後の更新：0xF9（netgd-fwupd、BBA / dcload）
               復旧：SD の NETGD.OGF（常駐部 B-SD、S3 以降に実装）
```

### 3-3 SWD が使えないと何が変わるか

- **最初の 1 回の書き込み手段が無い。** `0xF9` も `NETGD.OGF` も「NetGD（または常駐部）が既に動いている」ことが前提で、純正の上では何もできない。
- SAM3U の内蔵 ROM の SAM-BA（USB / UART）は GPNVM1 = 0 のときだけ起動する [一次、データシート §20]。純正は GPNVM1 = 1 でフラッシュから起動しているはずで、
  GPNVM1 を消す手段は SWD か ERASE だけ。6.0 で MCU の USB や UART0 がどこかに出ているかも不明 [不明]。→ **SWD の代わりにはならない**（ERASE の後なら、SWD が本当に壊れている場合の予備の書き込み経路として意味がある。§4-6）。
- TST ピンを使う FFPP（Fast Flash Programming、並列書き込み）は、多数のピンを外から駆動する工場向けの方式で、6.0 の実装済み基板では現実的でない。セキュリティビットが立っていれば FFPP も禁止される [一次]。
- NetGD 側で設計を変えて埋められる穴ではない。**変わるのは「ERASE の後に SWD が通るか」という一点**になる（§4、§5）。

## 4. 残っている非破壊の手（とリスク）

### 4-0 まず見直すこと：R177 の判断の重み

- R177 は「データシートではセキュリティビットは DP を切らないので、ロックだけでは説明しにくい」とした。データシート（doc6430、§9.1.3・§20.4.3.6）の文面はそう読める。
- 一方、**上流の作者は INSTALL.md §6（コミット `62b8e3d2`、2026-09-21）で、純正の基板は「デバッグポートが完全に切れる」「probe-rs は *target is not responding / device is locked*」「配線ミスではない」と書いている**。v5.x の純正・クローンを実際に扱った人の経験談と見られる [二次]。
- 他の Atmel/Microchip SAM でも「セキュリティを有効にすると SWD で DAP の IDCODE が読めなくなる」という報告がある（OpenOCD メーリングリストの SAMD20 の例、https://sourceforge.net/p/openocd/mailman/message/35700373 、検索要約）[二次]。SAM3U で同じかは未確認。
- → R177 の症状（DP が一切応答しない）は**「純正がロックしている」とまったく矛盾しない**。ただし、JTAGSEL・TST・Pico の故障も消えていないので、下の安い確認を先にする価値はある。
  **安い確認がすべて「異常なし」なら、ロックと見なして §5 の判断に進むのが妥当。**

### 4-1 Pico の自己テスト（既知の良いターゲット）— 最も安い

- 目的：Pico + debugprobe 2.3.1 + probe-rs 0.32.0 の組が SWD を正しく出しているかを、GDEMU と切り離して確かめる。
- 方法 A（**2 台目の RP2040 ボード**が最良）：debugprobe の Pico の GP2/GP3/GND を、別の Pico（または Tiny RP2040）の下端の **DEBUG パッド（SWCLK・GND・SWDIO）** へ。
  `probe-rs info --protocol swd` で RP2040 の DP（multidrop、`0x0BC12477` 系）が見えれば Pico 側は正常。
- 方法 B（1 台だけ）：debugprobe を動かしている Pico 自身の DEBUG パッドに、自分の GP2/GP3 をつなぐ。理屈の上では自分のコアの DP が見えるが、
  デバッグ操作で自分のファームを止める恐れがあり、`info` だけにとどめる。結果が曖昧なら方法 A に切り替える。
- 他の候補：手持ちの STM32 Blue Pill・Nucleo など SWD を持つ基板なら何でもよい。
- リスク：ほぼ無し（GDEMU に触らない）。注意は 3.3 V 同士であることだけ。
- 判定：見えない → Pico 側（配線・ファーム・GP 番号の取り違え）を直す。見える → GDEMU 側の要因に絞れる。

### 4-2 JTAGSEL（142）・TST（138）の確認

- 意味：JTAGSEL が High だと TAP は境界走査になり SW-DP は使えない。TST が High だとテスト／FFPP モード。どちらも通常品では基板上で GND に落とすのが普通で、
  クローンが意図的に引き上げている可能性は低いが、0 ではない [推測]。
- **無電源での抵抗測定だけにする**：Dreamcast から外した基板で、テスターの GND 側を 7 ピンヘッダ 7 番、もう片方を 142・138 番の**パッド側の根元**へ。
  0 Ω 付近 = GND 直結（正常）、数 kΩ〜数十 kΩ = プル、3.3 V 側の網と同じ値 = 引き上げの疑い。
- 道具：0.5 mm ピッチなので、**縫い針や細い針をテスター棒に巻き付けた「針先プローブ」**、ばね式の細いテストクリップ、ルーペか顕微鏡。
- リスク：
  - 通電中に測らない。隣のピンとのショートは、無電源なら害は小さいが、通電中なら MCU を壊しうる。
  - **ERASE（137）は 138 のすぐ隣**。無電源の抵抗測定で ERASE を一瞬触っても消去は起きない（ERASE は通電中に High が 220 ms 以上続いたときだけ効く [一次]）が、
    **通電中の測定や、測定器の電圧が乗った状態で電源を入れることは絶対にしない**。
  - 基板の裏から、ピンに出る配線やビアで測れるならその方が安全。
- 判定：どちらかが High 側 → それが原因の有力候補（ただし基板の改造が要り、本書では扱わない。ユーザーと別途相談）。両方 GND → 次へ。

### 4-3 connect-under-reset（NRST、ヘッダ 6 番の推定）

- 狙い：純正ファームが起動直後に SWD のピンを GPIO に切り替えている場合（SAM3U では PIO と共用のピンではないので**可能性は低い** [推測]）や、
  WDT・低電力で DP が不安定な場合に、リセット中に接続する。
- 前提の確認：ヘッダ 6 番が MCU 11 番（NRST）につながっているか、**無電源の導通**で確かめる（1・6 番は R115 で未確認）。
- 方針の注意：`fwbackup` は `--connect-under-reset` を**拒否する**（README の許可リスト）。手で `probe-rs info --connect-under-reset` を打つのは
  `fwbackup` の方針の外なので、実施するならユーザーの判断で、`info` だけにとどめる（`download`・`erase` は打たない。`SAM3U.yaml` には GPNVM を書き換えるアルゴリズムがある）。
  debugprobe（Pico）は NRST 出力を GP1 などに持つ版がある [推測、要確認]。手で NRST を GND に落としながら `info` を始め、離す方法もある。
- リスク：低い（リセットは純正を壊さない）。NRST を 3.3 V に直結しないこと（オープンドレインの入力に強く当てない）。
- 期待値：**セキュリティビットが原因なら、リセット中でも DP は見えない**（効果なし）。費用対効果は 4-1・4-2 より低い。

### 4-4 JTAG モードと境界走査の IDCODE

- SAM3U の TAP は、JTAGSEL = Low なら SWJ-DP（JTAG と SWD の両方）、JTAGSEL = High なら境界走査の TAP（IDCODE `0x05B2A03F`）[一次、データシート]。
- **JTAG（4 線）で試す**：ヘッダ 2 = TDI（R4 経由）、3 = TDO（R3 経由）、4 = TMS、5 = TCK、7 = GND（2・3 は推定。無電源の導通で MCU 1 番・4 番を先に確かめる）。
  - **Pico の debugprobe は SWD 専用**で JTAG は出せない。JTAG には、FT2232H / FT232H 系（OpenOCD）、J-Link、または RP2040 の JTAG 対応ファーム（例：dirtyJTAG・pico-dirtyJtag、
    OpenOCD の `cmsis-dap` で JTAG 対応の CMSIS-DAP 実装など）が要る。**ファームの導入は「信頼できる配布元から」かつユーザーの判断**（本書では入手しない）。
  - OpenOCD で `jtag newtap` を IDCODE なしで張り、走査で返る IDCODE を見るだけにする（`init` の後に `scan_chain`）。書き込みコマンドは使わない。
- 読み方：
  - `0x4BA00477`（Cortex-M3 の JTAG-DP）が見える → JTAG では DP が生きている。SWD 側（配線・プローブ）を疑う。ロックでもこの ID は返る可能性がある [推測]。
  - `0x05B2A03F` が見える → **JTAGSEL が High**。SW-DP が使えなかった理由がこれで確定する。
  - 何も返らない → JTAG でも無応答。ロック（実装によっては TAP ごと無効）か、TDO の経路の問題。
- リスク：低い（走査だけなら状態を変えない）。境界走査モードで `EXTEST` などを打つとピンを外から動かすので**絶対に打たない**。
- 費用：プローブの用意が要るので 4-1・4-2 より高い。

### 4-5 その他の小さな確認

- SWDIO・SWCLK の波形：手持ちのロジックアナライザ（安価な 8ch で十分）でヘッダ 4・5 番を見て、`probe-rs info` の最中に SWCLK のクロックと
  SWDIO の「ライン リセット → JTAG-to-SWD → 読み出し」の後に**ターゲットが ACK を返しているか**を見る。ACK が一度も来なければ MCU 側が応答していない、
  そもそもクロックが出ていなければ Pico 側。リスク：無し。費用：ロジアナがあれば最安クラス。
- R1・R2（約 95 kΩ）がプル抵抗としてどちらへ引いているか（3.3 V か GND か）を無電源で確認。SWDIO は通常プルアップ、SWCLK はプルダウン。逆でも致命的ではないが記録の価値はある。
- ボーレートを極端に下げる（1 kHz）・`--speed` を指定した複数回の試行。R177 で 10 kHz まで下げ済みなので、追加の期待値は低い。

### 4-6 破壊的な経路：ERASE（ユーザーの判断）

- 何が起きるか [一次、データシート・INSTALL §6]：通電中に ERASE（137）を High に 220 ms 以上保つと、**フラッシュ全体・ロックビット・GPNVM（セキュリティビットと GPNVM1）が消える**。
  純正ファーム（MCU 側）は**永久に失われる**。バックアップは存在せず（ロック中は読めない）、誰からも入手できない（本プロジェクトは入手しない）。
- 消した後：GPNVM1 = 0 なので ROM の SAM-BA から起動する。SWD が開いていれば INSTALL §7 で NetGD を書ける。
- **ERASE の後も SWD が見えない場合**、原因はロックではなかった（JTAGSEL・TST・配線・プローブ）ことになる。そのとき基板は純正も NetGD も無い状態になる。
  予備の経路は SAM-BA（USB の D+/D− か UART0 が基板のどこかに出ていれば）だが、6.0 では未確認 [不明]。→ **ERASE の前に §4-1・§4-2（と可能なら §4-5）を済ませておくべき理由**。
- 6.0 の FPGA（AG16K）について：外付けの SPI フラッシュが無く、MCU が FPGA にビットストリームを流す方式が有力（`docs/boards/gdemu60/README.md`）。
  その場合、純正のビットストリームも MCU のフラッシュの中にあり、ERASE で一緒に消える。NetGD 側の AG16K のビットストリームは Supra で作る計画だが、
  **6.0 の実ピンでの検証はまだ**（`docs/design/g1-ag16k-port.md`）。ERASE すると、NetGD が FPGA を起こせるようになるまで 6.0 は Dreamcast で何もしない。
- 物理的な注意：ERASE のテストパッドは U1 の左辺、137 番の高さとみられる（R177、未確定）。通電中に当てる操作なので、隣接ピン（136・138）への接触、
  3.3 V の直結（INSTALL は 1 kΩ 程度の直列抵抗を勧める）、ワイヤの外し忘れ（毎回消える）に注意。
- **これは実施を勧めるものではない。** 「純正の 6.0 を捨て、NetGD の AG16K 対応が実機で動くまで基板が使えない」ことを受け入れる場合だけの選択肢。

## 5. 推奨

### 5-1 順位（安く・壊さない順）

| 順位 | 手 | 費用 | リスク | 得られること |
|------|----|------|--------|--------------|
| 1 | §4-1 Pico の自己テスト（2 台目の RP2040 か SWD を持つ基板） | 小（手持ちがあれば 10 分） | 無し | プローブ側の故障を切り分け |
| 2 | §4-5 ロジアナで SWD の波形と ACK を見る（手持ちがあれば） | 小 | 無し | 「Pico が出していない」か「MCU が返していない」かが確定 |
| 3 | §4-2 JTAGSEL・TST の無電源の抵抗（針先プローブ） | 小〜中（細かい作業） | 低（無電源に限る。ERASE は隣） | 境界走査・テストモードの可能性を消す |
| 4 | ヘッダ 2・3・6 番の無電源の導通（MCU 1・4・11 番） | 小 | 低 | JTAG と NRST の準備 |
| 5 | §4-4 JTAG で IDCODE（JTAG 対応のプローブが要る） | 中（道具の用意） | 低（走査だけ） | JTAGSEL High の確定／JTAG-DP の有無 |
| 6 | §4-3 connect-under-reset（`info` だけ、`fwbackup` の外） | 小 | 低 | ロックなら効果なしと予想。期待値は低い |
| — | §4-6 ERASE | 小（作業） | **純正を永久に失う** | SWD が開けば NetGD を書ける。ユーザーの判断 |

- **公式の `GDEMU.FW` の経路（§1・§2）は導入経路にしない。** 6.0 で公式の更新を試すこともしない。

### 5-2 いちばん安い次の一手

**§4-1（Pico の自己テスト）**。2 台目の RP2040 ボードか、SWD を持つ適当な基板があれば、GDEMU に一切触れずに 10 分で終わる。
ロジアナがあれば §4-5 を同じ日に。

### 5-3 ユーザーに決めてもらうこと

1. 調査を再開するか（R177 で「時間の無駄だからいいよ」として中断した）。再開しないなら、6.0 は「純正のまま使う」で確定し、NetGD の 6.0 対応は机上（Supra・ホストテスト）だけ進める。
2. 再開するなら、§4-1・§4-2 をやるか。§4-4 のために JTAG 対応のプローブを用意するか。
3. `fwbackup` の方針の外の操作（connect-under-reset の `info`）を許すか。
4. **最終的に ERASE するか**：§4-1〜§4-2 が異常なしで DP が見えないなら、上流の作者の経験どおりロックと見るのが妥当。
   ERASE は純正の 6.0（MCU 側と、おそらく FPGA のビットストリームも）を永久に失う。NetGD の AG16K のビットストリームが実ピンで動くまで、基板は使えなくなる。
   **2 枚目の 6.0 を用意して、1 枚は純正のまま残す**のがいちばん後悔の少ないやり方 [推測]。
