# G2 書き込み性能の計画（F9〜F12 の前に何を測り、何から手を付けるか）

2026-11-22、Sonnet（M0 の実測は同日に反映。「M0 の実測」の節）。**調査と計画のみ。ファーム・FPGA・アプリのコードは変更していない**（LOG・PLAN も未変更。要約は呼び出し側が LOG に書き写すこと）。
**NetGD を実機で動かした確認はまだ無い**（PLAN「いまの状態」）。本書の速度は、「M0 の実測」の節の表を除いて「コード・仕様・純正の記録からの見積もり」で、`[コード]` `[純正の実測]` `[仕様]` `[推定]` `[未知]` の札を付ける。
ホストで取れた数字は 2.1 節の H1 だけ（模擬ディスクで数えたコマンド数）。

対象のコミット：`main` の `1a2bce03`。関連：`docs/design/bba-sd-write.md`（3.1 節、4.1 節 F9〜F12、9 章）、LOG R5・R8・R16・R38・R48・R62・R68・R80・R81・R99・R119〜R123、`docs/research/g3-read-path.md`（読み出し側の同種の見積もり）、`docs/research/flash-budget-2e.md`。

## 0. 要点（先に結論）

1. **律速は「MCU → SD」ではなく、DC 側の直列の鎖になりそう**（`/pc/` の fread → CRC・FNV → G1 書き込み → STATUS 照合 → 最後に全部読み戻し、が 1 本の同期処理）。ファームの SD 書き込みは、DMA のとき約 3〜4 MB/s の見積もり。**`/pc/` の fread は M0 で実測済み**（通常 1.9 MB/s、`-f` 5.0 MB/s）。残る最大の不確定は書き込みと読み戻し（未計測）で、設計書 3.1 の「律速は MCU → SD の書き込み」はコードを追うと言い切れない。
2. 設計書の F9〜F12 は**どれも効果が小さい**。F9（ACMD23）はカード次第、F10（DMAC 化）は MCU 側の時間を約 30 % 減らすが律速でなければ見えない（全体で +9 %）、F11（HS 50 MHz）は書き込みでは意図的に切ってある（+4 %）、F12（ログ）は 64 KiB/コマンドの経路ではほぼ無関係。
3. **効きそうなのはアプリ側（フラッシュ 0 B）**：読み戻しを軽くする（+42 %、未実測）。`/pc/` の読み出しと SD 書き込みの重ね（DMA 時、旧見積もり +56 %）は、M0 で CPU 計算相手に +0〜9 % しか出ず根拠を失った（「M0 の実測」の節）。**まず 0 B で測れるものを測る**。
4. **今できること**：(a) コマンド数の勘定（H1、**実施済み**）、(b) 時間モデルを模擬ディスクに載せる（H2）、(c) FPGA の書き込み FIFO の模擬（H3）、(d) Cortex-M3 のホットループの命令数（H4）。**NetGD 基板が無くても、DC + BBA だけで `/pc/` の読み出し速度と SH-4 の CRC 速度は実機で測れる**（M0。実施済み、R166・R167）。
5. 最初の一手は 5 章：**測定の道具を先に作る**（アプリの `NGD:PERF` と `bench`、ファームの `wr-prof`、SD 単体の書き込みベンチ）。**F9〜F12 は測定結果が出るまで着手しない**。

### M0 で変わった見積もり

- **読み**：「未知（0.5〜4 MB/s）」を実測に置き換えた。通常の 64 KiB は 1.9 MB/s（0.54 s/MiB）、`-f` の 16 KiB は 5.0 MB/s（0.20 s/MiB）。
- **CRC・FNV**：見積もりの 0.09 s/MB を実測 0.117 s/MiB（両方）に置き換えた。
- **「CRC と FNV で約 2.7 MB/s が上限」は誤り**。両方の計算だけの上限は約 8.7〜9.1 MB/s。2.7 MB/s は、`-f` の 16 KiB の読みと両方の計算を直列にした鎖の実測値。片方だけ計算すると、鎖は個別の和からの推定で約 +20〜25 %。どちらを残すかは設計（C1b・4.5 節の照合の役割）の問題で、本書は決めない。
- **重ね（C1c）**：旧見積もりの +56 % は根拠を失った。実測は CPU 計算相手で +0〜9 %、DMA 書き込み相手は未測定。C1c は保留のまま、DMA 書き込みと `/pc/` の同時実行を測ってから判断する。

中心のシナリオの再計算（秒 / MiB。書き込み＋STATUS と読み戻しは未実測の旧見積もりのまま）：

| シナリオ | 読み（ネット） | CRC・FNV | 書き込み＋STATUS | 読み戻し | 合計 | 速度 |
|---|---:|---:|---:|---:|---:|---:|
| 旧・中心（M0 前） | 0.40 | 0.09 | 0.31 | 0.33 | 1.13 | 0.88 MB/s |
| 中心・通常（64 KiB、1,894 KB/s） | 0.54 | 0.12 | 0.31 | 0.33 | 1.30 | 0.77 MB/s |
| 中心・`-f`（16 KiB、5,009 KB/s） | 0.20 | 0.12 | 0.31 | 0.33 | 0.96 | 1.04 MB/s |

読み取り方：
- 通常の 64 KiB のままだと中心の見積もりは 1 MB/s に届かない（0.77）。`-f` の 16 KiB なら届く（1.04）。ただし、書き込みと読み戻しが旧見積もりのままの値。`-f` は dc-tool-ip の設定で、NetGD の利用者の環境で使えるかは未確認。
- `read_bytes` の既定（64 KiB）は、通常では最良（16 KiB は 575 KB/s）。`-f` では 16 KiB が最良（5,009 KB/s、64 KiB は 4,639 KB/s）。つまみは `-f` の有無と組で決める。
- 読み戻しの軽量化（C1b、+42 %）の効果は、書き込みと読み戻しを実測するまで見積もり。

### 未測定（まだ推定）

- 書き込み（DMA・PIO）、MCU、STATUS、読み戻し、カードの持続書き込みはすべて未測定（M1〜M3）。
- UDP（netgd-send の本来の経路）は未測定。
- 通常モードの 1 回 26 ms の固定費の中身は、dc-tool-ip のソースで確認していない（§7.1）。

### 1.2 ファームの 1 セクタあたりの仕事

`ide.rs:4220-4296` のループは、1 セクタごとに次の順で**ひとつながり**に動く（`mw.feed` が返るまで次の処理に進めない）。

1. （PIO のみ）`set_status(DRDY|DSC|DRQ)` で DRQ を立てる（`:4243`）。DMA は DRQ 無しで、FPGA が FIFO の空きから DMARQ を出す。
2. `wait_host`：FIFO が 256 語以上になるまで `yield` で空回し（`:4246`。`poll_until` は眠らない、`:3991`）。
3. `set_status(BSY|…)`（`:4269`）。PIO ではこれが「次のセクタを待たせる」手段。
4. FIFO の語数を 2 回読んで確認（`:4276`）、256 語を 1 語ずつ SMC で読み出して `block` に詰める（`:4285-4290`）。
5. `wsession().write_data(&block)`：FNV-1a を 512 B に（`:4292`）。
6. `mw.feed(&block)`：128 語を TXRDY を見ながら `TDR` へ（`hsmci.rs:554`）。前のブロックのカードのビジーがあればここで待つ。

**PIO では DRQ を 6 の後まで立て直さないので、DC がセクタを送る時間と MCU・カードの時間が足し算になる**（DC は BSY が下りるまで `g1_ata_wait_nbsy` で待つ）。**DMA では 4 で FIFO が空いた時点から Holly が次のセクタを入れられるので、5・6 と重なる**（ただし FIFO は 1 セクタ分しか無く、重なるのは 1 セクタ分だけ）。

### 1.5 全体の見積もり（鎖が直列であることの効果）

```

```

`netgd-send collect` は `NGD:` の未知の行を無視する（R68 で確認済み）ので PC 側は変更不要。

## 3. F9〜F12 の位置づけ（用語の整理）

PLAN の「F9〜F12（書込性能、マウント解除・再スキャン、FIFO/DMA の書込経路）」は、括弧の内訳が設計書 4.1 節の定義と対応していない。**正本は設計書 4.1**：F9 = ACMD23、F10 = CMD25 の `feed` の DMAC 化、F11 = SD の HS モード（50 MHz）、F12 = 書き込み中の defmt ログ削減。「マウント解除・再スキャン」と「FIFO の深さ」には F の番号が無い。本書では次のとおり扱う：

- **F9〜F12**：4 章の C3（F9）、C5（F10）、C6（F11）、C8（F12）。
- **マウント解除・再スキャン**：4 章の C9。ファームの `WSESSION_END` の後の `load_media` / `load_by_name` の時間と、アプリの起動時の FAT 走査（`NGD:MOUNT ms=`、R68。`NGD:ALLOC ms=`、R80）。実行 1 回あたりの**固定費**（128 GB で 30〜60 秒の見積もり、R68）。1 本の大きなゲームでは 3 % 未満だが、小さなイメージを何本も送るときは支配的。
- **FIFO / DMA の書き込み経路**：4 章の C5（F10）と C7（FPGA の書き込み FIFO を深くする）。

## 6. 実機の事実との突き合わせ（LOG・PLAN で確認したこと）

- **NetGD を実機で動かした確認は無い**（PLAN「いまの状態」の最終行、「次の山場は実機」）。したがって F9〜F12 の効果だけでなく、書き込み経路の動作そのもの（F2 の FLUSH、F3 の DMA 公表、F5 のリセット後の再マウント）が未確認（R16）。本書の見積もりは**動くと仮定したうえでの値**。
- **純正の記録は読み出しだけ**（R117〜R123）。使った数字は CD_READ の PIO 約 14.0 ms / 32 KiB（2,278〜2,285 KiB/s）のみ。書き込み方向の G1 の値は無い（M4 で取る）。
- **BBA 速度の「実機確認済み」は ELF 送信の値**（R5、dcload-ip 2.0.3 で 4.3〜5.5 MB/s、HIT-0300 は約 1 MB/s）。**`/pc/` の fread は M0 で実測**（通常 1.9 MB/s、`-f` 5.0 MB/s、R166・R167。UDP は未測定）。
- **MCU → SD の書き込みは未計測**。設計書・`ide.rs` の「約 340 KB/s（CMD24 時代）」は CMD25 化の前の上限で、今の経路の実測ではない。`hsmci.rs:1067` の読み出し「約 2 MB/s」は古い注記で、`g3-read-path.md` は DMA で約 5.5 MB/s と見積もっている。
- **6.0 の MCU は 2E**（PLAN 冒頭）。測定機能を入れる余地は v60 ビルドにはあるが、2E の `resident,sd-fast` は余裕が 348 B（R100）。**FPGA を変える候補（C7）は 6.0 だけが対象**（Supra で AG16K を作れる、R99・R158）で、v5.5 の Cyclone II は再合成できない。かつ **6.0 は PS のピンとタイミングが未確定**（R49・R136）で、NetGD の FPGA がまだ載らない。
- **今の `main.rs` は FPGA の読み込みに失敗すると SD の初期化まで進まない**（`main.rs:149-188`）。SD 単体の測定（M1）にはこの順序を変える測定用ビルドが要る。
- **書き込みセッション中はボタンが無効**（F1、R16）。測定中に GD-ROM の媒体が戻らないよう、測定は必ず書き込みセッション（`WSESSION_BEGIN` の後）の中で行う。

## 7. 未確認（実機やソースの確認が要る点）
