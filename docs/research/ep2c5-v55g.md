## Pins (from the pad map, no hand edits)

- The 66 v5.5 signals at the F256 ball the pad map gives for their T144
  pin (`tools/pinfind/ep2c5_v55g.csv`), plus two g1gate inputs:
  `G_MASTERn` = R14 (MCU PA28), `G_WRAPn` = N8 (PA26), both weak pull-up ON.
- Outputs / bidirs: exactly 41 = 16 MCU_DATA (bidir, driven only while
  NCS3 and NRD are low), MCU_IRQn (tri-state; driven only with core_run
  set and outside wrapper mode) and the 24 G1 balls, all bidir (the pad
  input is the collision monitor's readback):
  INTRQ B4, DMARQ D11, IORDY A6, DATA0..15 (G10 A12 A14 C12 F15 D14 G16 D16
  E14 G15 B14 H13 B12 C13 C11 G11), CDCLK E1, SCK A3, SDAT B3, LRCK F3, EMPH D8.
- CURRENT_STRENGTH_NEW 4MA (the minimum LVTTL step) on each of the 24 G1
  balls; the gate reads "4mA" back from the fitter's Output / Bidir Pins
  tables. MCU side keeps the default (24 mA, as v5.5 and the proven scan cores).
- Weak pull-up ON only on R14, N8 and the MCU strobes NCS3, NRD, NWE, NBS0/1
  (a floating MCU pin reads idle, so the FPGA never drives MCU_DATA because
  of it). OFF on every DC_* ball (B4 per Run A's H1 verdict), the clocks,
  MCU_ADDR, MCU_DATA, MCU_RSTn. Bus hold off everywhere. Unused balls:
  RESERVED_INPUT, no pull-up (stage-0 options; v5.5 itself had
  unused pins "output driving ground").
- Clocks: H16 = CLK_48_MHz (PA21 / PCK0), J2 = CLK_11_2896_MHz (board
  crystal), both dedicated clock pads as on T144.
- PLL policy: exactly one PLL, `Audio_PLL` (x3, 33.8688 MHz), inclk0 =
  CLK_11_2896_MHz on its dedicated pin; its only load is the CDCLK path
  through g1gate (off by default). v5.5's `core_pll` is not instantiated
  (its output was unused; Quartus removed it in v5.5 too). Nothing is
  clocked by a PLL output except CDCLK's pad. The gate fails on any other
  PLL count, name or input.

## Safety design

Power-up: every register is 0 / idle (Verilog initial values), so after
configuration no G1 enable is set and none can be set until the MCU
issues wrapper commands.

Per G1 ball b:

```
pin_oe[b] = (engine_oe[b] | core_path[b]) & ~fault[b]
            & ~G_MASTERn(raw) & master(synced)
            & DC_RSTn(raw) & DC_RSTn(synced)
            & alive                       (H16 watchdog, J2 domain)
core_path[b] = core_run & ~engine_armed & grp_en[group(b)] & v5.5_oe[b]
```

- **Master (R14).** Must be held low. Releasing it (MCU reset / crash /
  `release_all` / nCONFIG / probe reset) removes every enable
  combinationally, with no clock; the synchronised copy also disarms the
  engine and clears every group enable (re-arming needs new commands).
- **DC_RSTn.** Same, combinational and synchronised; a fall also clears
  the groups and is counted.
- **H16 watchdog.** A divider of H16 is sampled by the J2 crystal; no
  change for 8 J2 cycles (709 ns; tb: off within 1.06 us) clears `alive`.
  It powers up "dead": H16 and J2 must both run before anything drives.
- **Core.** Held in reset unless MCU_RSTn is high **and** `core_run`
  (command 0xB4, 0 at configuration, cleared by 0xB5 / 0xB2). In wrapper
  mode (N8 low) the core's CS input is forced 0, so the MCU reads only
  g1gate's map and the two maps cannot collide.
- **Expiry.** Engine: 2^21 ticks (43.7 ms) or 2^27 (2.80 s) from the ARM;
  each group enable: ~2.8 s from its own enable command. No read
  extends either (tb reads status in a loop until expiry).
- **Engine limits by construction.** Pulse width 12 / 24 / 48 ticks
  (0.25 / 0.5 / 1 us) once per PERIOD = 48,000 ticks (1 ms): duty
  <= 0.1 %. DATA balls (any mode) only inside a Dreamcast AltStatus read:
  start = sampled qualification (CSn1 = 0, CSn0 = 1, A = 6, RDn = 0,
  WRn = DMACKn = 1), stop = the same qualification taken combinationally
  from the raw pads, so the drive ends with RDn's rise (or any CS / WR /
  DMACK / address change). IORDY only while the raw bus is idle
  (CSn0 = CSn1 = RDn = WRn = DMACKn = 1). ARM refuses (code in status)
  if the target ball does not rest at the level the table says.
- **Collision monitor.** Every G1 pad input, oe and value are sampled on
  both H16 edges. A sample counts only if oe and value were the same in
  the two samples before it (>= 1 tick settle; a clock-like core output
  such as CDCLK is therefore never compared). Two consecutive mismatching
  samples set `fault[b]` (sticky until reconfiguration), which removes
  that ball combinationally and stops the engine. tb: 62.5 ns from the
  enable edge against a held line (<= 3 ticks), 38 / 41 ns worst over
  three clock phases (the engine stops one tick after the fault) for contention starting mid-drive; 6 ns glitches do
  not fault. The first fault records ball, mode, ARM sequence number,
  pulse count and the 33 G1 levels. The counter side uses a registered
  copy (one tick later) for timing; the fault path is not delayed.
- **Sink-first order.** The engine needs no change for it: with the walk
  table, the low-going steps (IORDY, DATA, audio lines: sink against a
  high-resting line, +40 mA abs-max) can be run before the high-going
  INTRQ / DMARQ steps (source, -25 mA abs-max), as `cyclone2-drive-limits.md`
  recommends. The plan's walk order (G1 INTRQ first) is the firmware's
  choice; I recommend G3 -> G4 -> G5 -> G6 -> G1 -> G2.

## Wrapper read map (N8 low; addr = A8..A1; read-only)

Combinational from the address pins: 0x00 / 0x01 answer before H16 runs.
Counters can be torn by a concurrent update (read twice).

| addr | word |
|---|---|
| 0x00 | ID 0x5C55 |
| 0x01 | version 0x0001 |
| 0x02 | status: 0 armed, 1 driving, 2 done, 3 expired, 4 fault seen, 5 master (synced), 6 wrapper mode, 7 DC_RSTn, 8 H16 alive, 9 core_run, 10 DC_RSTn fell, 11 master dropped while armed, 15..12 last ARM result (0 ok, 1 no master, 2 DC_RSTn low, 3 bad ball / empty mask, 4 ball faulted, 5 level mismatch, 6 already armed, 7 H16 not alive) |
| 0x03 / 0x04 | fault[15:0] / fault[23:16] (ball index order below) |
| 0x05 | first fault: 15 valid, 14..13 mode, 12..8 ball, 7..0 ARM seq |
| 0x06..0x08 | first fault G1 levels [15:0], [31:16], {7'd0, [32], pulse count[7:0]} |
| 0x09 | staging: 12 long, 11 rest, 10..9 W, 8..7 mode, 4..0 ball |
| 0x0A | staging mask[15:8] / pattern[7:0] (DATA[7:0], mode 3) |
| 0x0B | ARM seq [15:8], staging N-1 [5:0] |
| 0x0C | engine timer (units of 2^13 ticks) |
| 0x0D / 0x0E | pulses or reads done / of those, readback followed |
| 0x0F | mismatching samples (16 bit, saturating) |
| 0x10 / 0x11 | valid compared samples [15:0] / [31:16] |
| 0x12..0x17 | AltStatus reads, other CS reads, CS writes, DMACKn falls, DC_RSTn falls, INTRQ rises (16 bit) |
| 0x18 / 0x19 / 0x1A | live G1 levels: DATA[15:0]; {DMACKn, WRn, RDn, CSn1, CSn0, A2..A0, EMPH, LRCK, SDAT, SCK, CDCLK, IORDY, DMARQ, INTRQ}; {RSTn, 2'b0, captures[2:0], 3'b0, grp_en[6:1], 0} |
| 0x1B / 0x1C | active: {mask, mode, W, 2'b0, rest, 0}; {ball, 5'b0, N-1} |
| 0x20..0x27 | capture k (first 4 non-AltStatus cycles): 0x20+2k {WR, CSn1, CSn0, A2..A0, 1}, 0x21+2k DATA (write data at WRn rise) |
| 0x30..0x3F | walking 1 (`1 << (addr & 15)`) |
| other < 0x40 | `{0xA5, addr}` |
| 0x40..0xFF | commands (read returns status) |

## Commands (reads; executed at the end of the read in the H16 domain; address stable >= 2 ticks)

| addr | effect |
|---|---|
| 0x40+n / 0x50+n | pattern[3:0] / [7:4] = n |
| 0x60+n / 0x70+n | mask[3:0] / [7:4] = n |
| 0x80+b | ball b (0..23) |
| 0xA0+m | mode m: 0 passive (N+1 periods, nothing driven), 1 level-match (drive the rest level: N+1 ms, or N+1 reads on DATA), 2 opposite pulses (N+1 pulses of W, one per ms; on DATA: N+1 reads), 3 pattern on masked DATA[7:0] in N+1 AltStatus reads (Phase C) |
| 0xA4+w | W: 0 0.25 us, 1 0.5 us, 2 / 3 1 us |
| 0xA8 / 0xA9 | rest level 0 / 1 (checked against the ball at ARM) |
| 0xAA / 0xAB | expiry short 43.7 ms / long 2.80 s |
| 0xC0+n | N-1 = n (1..64) |
| 0xB0 | ARM (result in status 15..12) |
| 0xB1 | STOP engine |
| 0xB2 | release all: engine off, groups off, core_run off |
| 0xB3 | clear counters, captures, sticky flags (not faults) |
| 0xB4 / 0xB5 | core_run on / off |
| 0xB9..0xBE | group 1..6 enable (needs master, DC_RSTn; expires ~2.8 s) |
| 0xB8 | all groups off |

Ball index: 0 INTRQ, 1 DMARQ, 2 IORDY, 3..18 DATA0..15, 19 CDCLK, 20 SCK,
21 SDAT, 22 LRCK, 23 EMPH. Groups: 1 INTRQ, 2 DMARQ, 3 IORDY, 4 DATA[7:0],
5 DATA[15:8], 6 audio.

Walk step for the firmware (one ball): PA30 low, PA26 low; check 0x00 /
0x02 before PCK0 and before PA28; then `0x80+b, 0xA0+mode, 0xA4+w,
0xA8+rest, 0xAA, 0xC0+n, 0xB0`, read 0x02 until bit 0 clears, read
0x02 / 0x03 / 0x04 / 0x0D / 0x0E / 0x0F; abort on any fault bit.

## Flash fit (main schedule risk)

- LZMA with the firmware's filter (`mcu/netgd/build.rs`: raw LZMA1,
  preset 9e, 4 KiB dictionary, lc0 lp0 pb0): **67,348 bytes** (CI and
  local agree). For comparison: v5.5 T144 `OpenGDEMU.rbf` 74,685 -> 51,372;
  scan2 v0 84,146 -> 63,353 (already embedded by the sweep-12 firmware);
  scan 68,796 -> 42,394. The fuller device (97 % LEs) compresses worse.
- Estimate: ~40 KB firmware text + 67.3 KB = **~107 KB of the 128 KB
  flash**, i.e. ~21 KB free (about 15 KB if the pin-finder image is held to
  the 122,880-byte application region). Run 4 fits **only if it replaces
  the scan2 streams**: sweep 12 carried ~69.8 KB of bitstreams (scan2 v0
  63.4 KB + v1 / v2 prefixes ~3.1 KB + stage0 3.3 KB), so v55g instead of
  them is about -2.5 KB against the build that already links. Keeping
  scan2 v0 beside v55g (131 KB of streams) does not fit.
- Levers if it gets tight: drop stage0 / AG16K tables from the run4 build;
  build v55g with on-chip decompression OFF (build.rs notes LZMA on the raw
  stream lands ~5 KB smaller for v5.5, at 2x PS clock time); trim g1gate's
  captures / counters (also frees LEs).
- Not measured: the actual `pinfind_run4` link (firmware not written).

## Open risks

- Nothing G1-side is proven: the readback / monitor sees only the FPGA
  pad, not the connector (series parts on 6.0 would hide a contention).
- Sourcing pulses (INTRQ / DMARQ high) are near the -25 mA abs-max if the
  ball is really a Holly output; the 4 mA setting and 1 us / 0.1 % duty
  bound the energy, not the peak.
- The 4mA setting's real drive is unmodelled (no IBIS check done).
- 96 % LEs: little room for more g1gate logic; a later change may need
  the counters / captures cut.
- Metastability: pad samples use a single flop each (speed); a metastable
  sample can only add or drop one compared sample.
- The group enables expire after ~2.8 s, so the NetGD main firmware would
  need a periodic re-enable path (wrapper mode) or a later image without
  expiry; out of scope for Run B / C.
- Commands are executed from H16-sampled MCU strobes: NRD must stay low
  >= 3 ticks (~63 ns) with a stable address; the scan cores' reads were ~94 ns.
