NetGD · GDEMU 6.0

あなたにお願いしたい実機作業

NetGD は、まだ実機で一度も動作を確かめていません。ここから先に進むには、手元の GDEMU 6.0 と Dreamcast を使った作業が必要です。 上から順に進めてください。チェックと記入した内容はこのブラウザに保存されます。最後に「結果をコピー」で Claude に渡してください。

1純正 GDEMU をプローブで調べる配線なし。Dreamcast + BBA だけ 2テスターで導通を確認する電源を切った基板で。G1 の進め方が決まる 3SWD プローブを用意する最初の書き込み用。2 の結果が必要
3つの作業すべてに共通する注意 純正ファームは吸い出せず、消えたら元に戻せません。ERASE パッド（MCU の 137 番ピン）に電圧をかけないこと、純正に未知のコマンドを送らないことを守ってください。この3つの作業は、どれも純正ファームを消さずにできます。

純正 GDEMU をプローブで調べる

ツールあり（初回ビルドが検証）
所要 約 1〜2 時間（初回）場所 DreamSDK のある PC + Dreamcast手順書 docs/research/stock-gdemu-flow.md

純正ファームの GDEMU が返す応答の「正解データ」を集めます。Dreamcast 上の小さなプログラム（tools/gdprobe）が GD-ROM に読み取り系のコマンドだけを送り、結果を BBA 経由で PC に保存します。

応答の食い違い D-1〜D-5

本家の性能の基準値
読み込み速度、シーク時間（G3 の比較相手）

準備するもの

  • DreamSDK が入った PC と、あなたの Dreamcast-Dev-Tools-for-BBA
  • Dreamcast、ブロードバンドアダプタ（HIT-0400 / 0401）、LAN ケーブル
  • GDEMU 6.0（純正ファームのまま）
  • 調査用の SD カードを別に1枚（MBR パーティションありの FAT32。普段使いのカードは変えない）

イメージは自分で所有するディスクから作ったもの、または配布が許されたホームブリューだけを使ってください。SD に入れたのと同じファイルを PC にも残しておくと、読み出したデータの照合ができます。

テスターで導通を確認する

いつでもできる
所要 約 1 時間道具 導通ブザー付きテスター、先の細いプローブ、ルーペ写真 docs/boards/gdemu60/top.jpg

基板の表記が無いヘッダが、MCU（U1：ATSAM3U2E）のどのピンにつながっているかを調べます。これで SWD（書き込み）・UART（ログ）・ERASE パッドの場所と、FPGA の起動方式の手がかりが分かり、GDEMU 6.0 対応（G1）の進め方が決まります。

電源を切った状態でだけ測る GDEMU を Dreamcast から外し、SD カードも抜いて、電源が入っていない状態で測ってください。ERASE につながるパッドが見つかっても、そこに電圧をかけないでください（純正ファームが消えます）。 テスターを当てるだけなら安全です。ERASE（137 番）は内部で 15 kΩ のプルダウンがあり、電源が入った状態で 220 ms 以上 High にしないと動きません（データシート）。ただし隣の 136 番（SHDN）と 138 番（TST）にはプローブの先を滑らせないでください。TST が電源投入時に High だと、書き込みモードに入ります。

MCU のピン番号の数え方

U1 は 144 ピンの LQFP です。チップの角にある丸いくぼみ（写真 top.jpg では U1 の右下、白い点の近く）の隣が 1 番で、上から見て反時計回りに 1 辺 36 本ずつ数えます（1〜36、37〜72、73〜108、109〜144）。

調べる MCU のピン

ピン番号は SAM3U のデータシート（Atmel-6430G、表 4-1「144-lead LQFP Pinout」）から取りました。v5.5 クローンでの接続は上流の docs/PCB.md の記録です。

  1. v5.5 では H1（7 ピン SWD）・H2（3 ピン）・H3（5 ピン）・H4（3 ピン UART）でした。6.0 の 5 / 3 / 8 / 2 ピンも、これらに対応している可能性があります。まず各ヘッダの全ピンから SWDIO（7 番）を探し、見つかったヘッダで SWCLK（9 番）と NRST（11 番）を確かめると早く進みます。
  3. ヘッダの 1 番は、写真 top.jpg の向き（「GDEMU 6.0」の文字が右）で、横に並ぶものは左端、縦に並ぶものは上端とします。どれにもつながらなければ「なし」と書いてください。
  5. FPGA（U2）は BGA なので、ボールに直接は当てられません。MCU のピンから出た配線やビア（小さな穴）がどこへ向かうかを、ルーペと写真で追ってください。どこにもつながっていなければ、FPGA は内蔵メモリから自分で起動している可能性が高くなります。分かった範囲で構いません。

SWD プローブを用意する

2 の後
所要 約 30 分費用 Raspberry Pi Pico 1枚（数百円）とジャンパー線詳細 INSTALL.md §2・§5

NetGD の最初の書き込みには SWD プローブが要ります（2回目以降は BBA 経由で更新できます）。ここでは準備と、純正ファームを消さずにできる確認までを行います。

この段階では ERASE をしない INSTALL.md の §6（純正ファームの消去）は、NetGD を書き込むと決めるまで行いません。ここで行う CHIPID の読み出しは、読み取りだけなので純正ファームには影響しません。
  2. raspberrypi/debugprobe のリリースから debugprobe_on_pico.uf2（Pico 2 は _on_pico2）を取得 → BOOTSEL を押しながら USB を挿す → 出てきたドライブにコピー。古い picoprobe.uf2 は使えません。
  3. probe-rs のリリースから Windows 用の probe-rs-tools を取得して PATH に置きます。debugprobe は CMSIS-DAP v2 なので、Windows でもドライバは不要です。probe-rs list に何も出ないときだけ、ドライバ（Zadig など）を疑ってください。
    probe-rs list
  4. Pico の GP3 = SWDIO、GP2 = SWCLK、GND。3.3 V はつながない（基板の電源は Dreamcast から取る。INSTALL.md §4）。
  5. probe-rs read --chip ATSAM3U2E --protocol swd b32 0x400e0740 1
probe-rs info --verbose
    6.0 の MCU は 2E なので --chip ATSAM3U2E です（INSTALL.md の ATSAM3U4E は v5.5 用）。--connect-under-reset などのリセットを伴うオプションは付けないでください。どの結果でも分かることがあります。出力は全文を Claude に貼ってください。
    結果意味
    281a0761SAM3U2E で、純正はフラッシュをロックしていない。この場合は純正ファームを丸ごと読み出して保存できる可能性が高いので、何かを書き込む前に、まず Claude と読み出しコマンドを確認してバックアップを取る（フラッシュ 128 KB、読み取りだけ）
    28100961 など 2810…4E が載っている（写真と矛盾。刻印を見直す）
    読み出しは失敗、info --verbose でデバッグポート（DP）は見える純正がロックしている可能性が高い。書き込みには ERASE が必要
    DP も見えない配線・電源（Dreamcast の電源が入っているか）・JTAGSEL（142 番）を疑う
